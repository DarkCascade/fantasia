PROJECT: Design, balance, and package an original board game played with a standard deck of playing cards, plus a matching set of 3D-printable character miniatures.

THEME: [your theme here, or "pick an original theme that suits 2–4 players and 30–45 minutes"]

PART 1 — DESIGN THE GAME
- Target: 2–4 players, 30–45 minutes, ages 12+, simple enough to teach in 10 minutes.
- The game uses one standard 52-card deck (jokers optional) as its only cards. Don't design custom cards. Give suits, ranks, and face cards their meaning through the rules, e.g. suits as resource types or actions, rank as strength or movement, face cards as special events.
- All card meanings must work from printed reference materials. Players should never need to mark or modify the cards.
- Each player controls one distinctive character with an asymmetric ability, ideally tied to how they use the deck (e.g. one character treats hearts as wild, another can play pairs as a single action). Plan for 4–6 characters so there's choice at setup, and add 1–3 neutral or boss figures if the design calls for them.
- Other components should be printable or common household items (a printed board, tokens you can cut out, coins, or dice if needed).
- Write a complete first draft of the rules before building anything else.

PART 2 — BALANCE IT BY SIMULATION
- Write a simulator that implements the rules exactly, using a correctly modeled 52-card deck (plus jokers if used), with shuffling, dealing, and reshuffle rules as written.
- Build at least three AI strategies, e.g. greedy, cautious, and one that exploits each character's ability.
- Run at least 10,000 games per configuration (every player count and character pairing that matters).
- Estimate real-world playtime from turn counts (assume about 30–60 seconds per turn, and state your assumption). Adjust the rules until typical games land in 30–45 minutes.
- Look for: characters winning more than ±5% from an even share, dominant strategies, runaway leaders, stalled or overlong games, suits or ranks that are almost always or never worth playing, and deck-luck swings large enough to override player decisions.
- Revise the rules and re-run. Repeat until the targets are met or you can explain why a remaining imbalance is acceptable.
- Keep a changelog of each iteration: what the data showed, what you changed, and the result.

PART 3 — PRINTED MATERIALS
- Rulebook PDF with components list, setup diagram, turn summary, and worked examples that show specific cards being played.
- Card effects reference sheet: a clear chart of what every suit, rank, face card, and joker does, printed one per player.
- Board as a print-ready PDF (it can tile across multiple letter/A4 sheets with alignment marks).
- One-page player aid per character, explaining its ability with a card-based example.
- Any other printed components the game needs (score tracks, tokens to cut out, event tables), with cut marks where relevant.
- "Designer's Notes" PDF summarizing the balancing story, with charts of win rates and game length before and after.

PART 4 — MINIATURE PROMPTS FOR MESHY (text-to-3D)
For every character and neutral figure, write a Meshy text prompt that yields a model suitable for resin or FDM printing at roughly 32mm scale.
- Start every prompt with the same style prefix so the set looks unified. Write it yourself to fit the theme (e.g. "stylized chunky tabletop miniature, heroic proportions, sculpted detail, ...").
- Printability rules to state in each prompt: a single standing figure on an integrated round base; a compact pose with limbs close to the body; no thin or free-floating parts (no loose strands, thin weapons, or wide capes); thick, sturdy props; no background or scenery; no text.
- The character's in-game role should be readable from the silhouette. Where it fits, echo its card affinity in the design (e.g. a spade motif on the shield of a character tied to spades).
- For each figure also provide: a negative prompt (if Meshy supports one), the intended height in mm, a one-line tie to the character's in-game ability, and a short painting color scheme that matches that character's player aid.
- Deliver these as a "Miniatures Guide" PDF plus a plain .txt file with just the prompts, one per line, ready to copy.

PART 5 — VERIFY
- Re-run the simulator on the final rules and confirm the numbers in the Designer's Notes, including the playtime estimate.
- Open every PDF and check layout, cut marks, and board tile alignment.
- Confirm that the rulebook, card reference sheet, and player aids all match the simulated rules exactly, with no card meaning that differs between documents.
- Check each Meshy prompt against the printability rules.

DELIVERABLES: rulebook PDF, card effects reference sheet PDF, board PDF, player aids PDF, other printed components PDF (if any), Designer's Notes PDF, Miniatures Guide PDF, prompts .txt, and the simulator source code.
